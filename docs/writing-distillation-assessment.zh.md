# 写作蒸馏如何改进一般研究工作流

这次评估把 scientific-writing-library 的已审核表达方法应用于 ResearchFlow 和 research-assistant-maf。库本身是来源可追溯的表达、搭配和论证资源，并没有一个可直接安装的独立 `SKILL.md`。本次把其中能够改变研究判断和写作行为的方法提炼到两个仓库已有的 skill 中，保留按需加载。

## 结论与增量

有帮助，但主要帮助来自恢复句子背后的研究操作，而不是增加模板数量。两个仓库已经具备证据层级、负面结果、研究对象、章节依赖和补证机制。新增内容着重处理原先没有直接分发或演示的一段交接：**研究判断如何转成一个简洁、可比较、有证据边界的段落，以及写作发现的缺口如何回到研究任务。**

| 位置 | 原有能力 | 本次增量 |
| --- | --- | --- |
| ResearchFlow | 问题、有限任务、证据绑定、主张处置、补证 | 按段落读者任务检查证据、允许推论和措辞；用现有交接协议登记写作，不新增科学判分器 |
| MAF | 工作流图、角色分工、显式写作范围、章节指导 | 将短的论证蒸馏方法按章节直接送到角色；保留来源所在章节与推荐应用章节的区别 |
| 案例 | 扩散治理演示、已有 AMMT 写作记录 | 增加会诱发错误推广的案例及实际稿件改写；保留历史记录，区分合成数据、模型执行和编辑判断 |

库中 570 个表达条目不能全部塞进每项任务；词频、顶刊身份、来源短锚点匹配也不能证明科研主张。专业术语应跟随当前研究对象选择。熔池搭配、逆向设计采样规则、某篇论文的样本量，都不应成为通用研究项目的强制流程。

## 提炼后的一般流程

以下各项可合并、回退或按任务省略，不是固定阶段或每段必填表格。

1. **定位读者需要作出的判断。** 将研究问题变为具体对象、响应、参照、条件及待区分的解释。背景段落需要导出这个判断；方法段落需要让它可核查；结果段落需要回答它。
2. **调查最接近的前驱与实际证据。** 读相关正文、方程和图表，区分前人已经解决的问题与仍未区分的方面。承认已有成功，再解释其边界为何影响当前判断。按来源记录事实、推断与新提案。
3. **选择能改变理解的下一任务。** 需要补证时明确缺哪个量或对照、哪些条件保持、什么结果会改变判断。纯粹换措辞或重复微调而不改变理解时，重新检查问题和比较设计。
4. **执行并评估证据的实际用途。** 训练标签、标定数据、独立重算、实验核查承担不同角色；数值守恒、误差和物理吻合也回答不同问题。核对聚合与筛选规则，保留失败和反例。
5. **把判断交给写作者。** 对重要段落共享用途、证据定位、比较身份、允许推论、尚未支持的解释，以及相邻段落需要承接的信息。通常可写在现有结果文件中，无需新状态协议。
6. **先形成命题，再选择表达。** 技术对象与动作明确后，再选句式、搭配、动词和介词。连词应对应真实关系；压缩前后核对条件、数据用途、统计含义和反证。短句不能把最佳样本变成平均表现，或把研究目标变成已实现效果。
7. **独立重建论证并处置。** 评阅者从实际输入、稿件和相邻段落恢复论证；协调者检查 Introduction 的问题、Methods 的比较、Results 的答案和 Conclusion 的范围是否一致。交付接受与科学主张支持分别记录；关键缺口按影响范围返回研究。

原有运行时仍负责任务和文件版本绑定。科学解释由领域角色与协调者判断，不能由 JSON 完整性、流畅度或某个动词决定。

## 验证记录

ResearchFlow完整42项测试通过，实际CLI交接未闭合/闭合时audit分别退出2/0。MAF完整102项测试与8组手工标注的语义反例通过，实际离线图两轮完成。源码目录外的wheel安装、章节选择和来源资源检查通过；这些验证没有把确定性示例称为模型写作。

独立同模型agent实际完成11项合成写作请求，未得到期望答案或测试源码。协调者读回段落与原始输入，接受其限定交付。W9发现严格阈值未定义，已明确为error < 5%并独立单项重测；原11项记录保留。代码审查另外修正有限候选筛选不能建立唯一性；独立框架评阅发现反例检查条件写反，随后修正并重查。

原生MAF模型入口实际尝试后，Codex SDK因C盘已满无法初始化SQLite状态，0个完成模型回合、0个改稿产物；失败ledger保留，不自动重放。实际稿件改写改由当前桌面agent执行，使用真实MAF loader分发的guidance，不能计为原生MAF成功运行。

测试通过只支持其覆盖的程序行为或有限案例表现，不证明因果性的写作质量提升、普遍可靠率或论文接收。现有writer guidance仍偏长，全文约8.8万字符；本次避免注入整库，但没有解决全部上下文精简问题。
