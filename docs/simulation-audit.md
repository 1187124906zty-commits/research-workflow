# 模拟执行组件的效率与证据边界审查

审查对象是用户已有的 `simulation-project-orchestrator`。本次将原 skill 完整复制到仓库的 `skills/simulation-project-orchestrator` 后修改；未直接改动安装目录，也未修改其外部 `simulation-agent-mvp` 程序。原有脚本、schemas 和示例保留。

原组件已经具备很好的方程、来源、数据角色与论断追溯意识，问题主要是不同任务规模的规则混在入口：一个探索性计算容易继承正式复现、最终机制证明与严格运行时治理的全部要求。效率改进要改变任务与证据的适用范围，而不是把失败改成成功。

## 已定位的问题与修改

| 原规则或冲突 | 对研究执行的影响 | 本次调整 |
|---|---|---|
| 入口要求实物问题在 solver 生成前有独立分析者和完整冻结机制方案 | 尚不清楚机制的想法无法先取得探索证据；额外角色与文件成为前置 | 探索先规定一个物理问题和最低有用输出；正式机制论断仍需可反驳预测、竞争解释、诊断和独立审阅 |
| 编译完整项目对象、冻结获批规格、泛化人工检查点 | 可逆建模选择反复等待，研究方向被过早固定 | 小任务可将规格、物理契约、证据依赖写在同一运行计划中；冻结一次可复现运行，假设变化建立新版本；尊重用户已有授权 |
| 每个实质任务需要精细模型路由、能力证明、digest 和完整治理 bundle | 科学工作受路由证明和记录成本拖累；普通任务也被当成控制层验收 | 默认沿用已配置模型；普通任务用简短契约、版本定位和证据交接；严格 schema/内容绑定仅在实际适配器或用途需要时加载 |
| 已有按案例设阈值的原则，但没有明确将数值精度与当前研究判断相连 | worker 仍可无限优化残差或追逐参考论文数值设置 | 对每个 QoI 说明效应/决策尺度、数值变化、其他不确定性和继续计算的信息收益；阈值不得事后放宽来拯救失败 |
| 原规则按修复预算停止，但“进展”可能只指局部诊断变好 | 改善小数位仍被当作值得继续的进展 | 两轮连续修复/细化未改变可行性、论断支持、解释区分或下一研究行动时，返回主协调者；新一轮需要新的有限契约 |
| 治理参考的结尾把 local MVP 的全 PASS 规则放在通用工作流中 | 普通 WARN 或记录保证不足可能阻断整个论文项目 | 区分普通科研的逐论断规则与外部 MVP 的真实程序限制；开放请求和失败只影响对应论断及依赖 |
| 对话 audit 输出整体 BLOCKED，原说明不够强调范围 | 无关未答问题也可能被解释成全局不可推进 | 保留 audit 程序不变，明确将开放 thread 映射到受影响论断，或使用按论断分开的 ledger；不把结构检查当作科学判断 |
| 入口存在 `runtime-execution-contract.md` 断链 | subprocess 运行规则被引用但无法读取 | 补充实际有用的运行时契约：真实能力探测、稳定输入、原生日志与输出、先保存证据、分离执行与科学验收 |

新增 `references/research-efficiency.md` 统一说明 exploration、paper_formation、submission 的证据用途与返回条件。原机制、preflight、gates、项目对象、结果包装和对话参考同步修订，避免只缩短入口却被旧细则重新拉回一刀切流程。领域研究、应用策略、方法审查、文献验证的原有内容保留，按任务需要渐进加载。

## 保留的科学约束

单位、控制方程、必要物理闭合、初始/边界/界面条件、适用物理范围、方程与实现映射、来源真实性、原始输出、校准与验证隔离、量测算子、反证和失效历史仍然约束对应论断。探索性假设需要显式标签，不能被称为实验事实。负面结果可被接受为有用交付，同时被否定的假设或失败 Gate 保持原状态。

主协调者可以调整优先级、提出下一实验、退役较宽论断；它不能通过投票、模型等级、预算耗尽或更强措辞来消除事实失败。数值执行者返回证据，机制/论文请求者解释证据并完成 disposition。

## 剩余实现边界

`simulation-agent-mvp` 是外部程序，原全 PASS 规则、模型能力字段、运行时保证和 `EXECUTED` promotion cap 未被修改或实际运行验证。本 skill 明确保留这些限制，不能靠新指令绕过其返回状态；普通阶段策略也不能使不符合其 schema 的简短记录突然成为兼容 bundle。

这些指令改善决策和协作约束，不能阻止任意 agent 绕开任务记录直接调用 solver，也不能自动判定效应尺度、方程是否正确或机制是否唯一。确定性检查负责记录和依赖，领域判断仍需原始证据、有限实验和 consequential review。此组件不保证选题创新、稿件接收或发表。
