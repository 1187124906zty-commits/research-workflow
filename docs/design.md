# 从问题到具体治理机制

## 先处理的问题

1. **局部优化吞噬全局。** 执行者缺少当前科学问题、效应与误差的关系、返回点和继续投入的理由。解决方式不是降低所有精度，而是任务契约、研究阶段、逐论断的要求和无进展重审。
2. **研究并非一次冻结的流水线。** 阅读、工具试用、结果与解释都可能改变问题。固定一次 run 的输入，保持问题和论文论证可版本化演化；负面结果是有价值的回传。
3. **写论文需要研究读者。** PaperSpine 从选题阶段参与读者、期刊、贡献与图表证据设计。后续写作回传证据缺口，并明确期刊硬要求与有限样本推断的区别。
4. **上下文影响判断。** 共享状态保存目的、事实、假设、反证、下一判断和定位；worker只拿相关原文、有限背景和任务契约。恢复时优先看未处置交接、失效论断与当前证据。
5. **协作不是叠加 agent。** 主协调者负责全局判断和单写入者状态；按需启用文献、写作、证据、机制和审稿责任。独立任务并行，依赖任务顺序执行；模型继承用户选择，不按名字赋予真理权威。
6. **提示词不能代替执行机制。** AGENTS 自动入口 + skill渐进披露 + 角色指令 + 实际持久运行时分别解决发现、判断、责任和可检查状态。程序只能校验它看得到的事实，科学解释仍需模型和原始证据。

## 为什么不采用统一严格程度

探索时先问工具是否能表达问题、信号是否值得追踪；形成论文时再确认对照、误差、复现与论证；投稿前核查每个主张、图表和格式。对于安全或高后果用途，科学充分性仍按相应用途提高，不能被探索阶段绕开。阶段是任务的理由，不是免检标签。

研究判断包含“哪种行动最能区分解释、影响论证、且能承担成本”。不把它简化为一个随意打分的优先级公式，也不把所有未完成事项升级成全局阻断。只有具体作用范围可辨的证据缺口才阻断对应结论；其他有价值工作继续。

## Codex 接入依据

已核对安装环境为 Codex CLI 0.159.0，官方文档检索日期为 2026-10-01。

- [AGENTS.md](https://developers.openai.com/codex/guides/agents-md)：全局/项目指令在运行开始时发现；`AGENTS.override.md` 优先；默认合并长度有限。安装器只追加简短的条件入口，不复制整套框架到常驻上下文。
- [Skills](https://developers.openai.com/codex/skills)：描述用于匹配，正文和参考渐进加载。当前文档推荐 `.agents/skills`；本机目录实际采用 `.codex/skills`，安装器允许选择兼容布局，项目安装使用当前文档布局。
- [Subagents](https://developers.openai.com/codex/multi-agent)：可由用户或适用 AGENTS/skill 指令触发；standalone `.codex/agents/*.toml` 要求 `name`、`description`、`developer_instructions`，可继承父 agent 的模型和权限。五份角色文件没有设置模型和权限。

角色配置支持与提示词分工是两件事。本次实现中的 subagent 通过实际 collaboration dispatch 得到角色与契约；单纯 TOML 语法校验不等于每个客户端都已实测加载这些角色。若某客户端无法发现角色，协调者可以直接使用相同职责文本进行 bounded dispatch，并报告配置发现差异。

## 程序约束的范围

运行时记录单写入者状态，检查任务依赖、有限预算、证据版本和影响范围，保存 requester disposition。证据文件绑定使用内容版本用于多 agent 交接中可能被改动的证据；不会用散列代替物理测试或对所有普通文档重复校验。

程序不知道某篇论文是否支持一个机理，也不知道一次实验是否充分识别因果。它能拒绝缺文件、陈旧引用或已记录 blocker 下的提升，不能自动识别未报告的错误。必须运行真实工具并由负有责任的角色解释。未来若接入统一 MCP 求解器入口，可在调用边界进一步强制 contract/audit；本版本不声称已经提供该拦截层。

本仓库不修改 PaperSpine 的 managed分发、不创建伪用户选择，也不替旧模拟原型解除其全部 PASS 限制。可检查的接入边界是软件质量的一部分。
