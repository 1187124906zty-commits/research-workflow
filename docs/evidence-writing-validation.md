# 写作衔接与技能更新验证

核对日期：2026-10-10。ResearchFlow保持研究问题、证据和共享状态的责任；具体写作使用通用research-writing-skill，缺失时才使用本包的短回退。writing-integration管理交接，evidence-writing只保留会影响科学主张的支持区别。重复的scientific-story-handoffs已退休，现行规范没有继续叠加案例指令。

## 实际验证

Windows bundled Python 3.12完整执行55项unittest，退出0。覆盖研究状态、反证传播、交接处置、编辑接收不能提升科学验证、上游变化使旧支持失效、安装迁移及科学对话的重新打开和分支责任。完整测试安装可选依赖`.[simulation]`；核心researchflow运行时仍无第三方依赖。

实际运行researchflow CLI帮助，以及科学对话审计CLI对已闭合的合成重新打开案例。审计返回结构PASS、DIALOGUE_COMPLETE；它只确认请求和答复责任闭合，不证明数值或物理正确。五个技能通过官方frontmatter校验，安装迁移测试保留未知自定义文件，仅移走明确退休文件。

独立写作角色接收既有合成研究的现行稿、原始输入与相关图件关系，完成讨论首段的实际修订。返回把响应吻合、参数恢复和标定依据连接起来，并指出方法框图与参数准确度证据承担不同任务。写作者使用writing-integration和通用技能，没有创建新产品、研究intake或作者访谈；协调者读回段落和相邻讨论后接收该局部交接。

## 更新范围

仿真依赖同步为协调入口、资料准备、工具执行、结果验证四个技能；每个角色只读本职入口和必要原件。安装器声明退休文件迁移并处理Windows长路径。源代码、技能目录与本机受管理副本逐项比对；私人稿件、原始研究运行目录和托管PaperSpine产品没有进入发布。

软件测试说明执行与绑定可靠，局部试用说明一次接口能够完成指定写作任务。两者都不能证明任意长篇论文质量、跨领域可靠率或科学真值。来源例文不能替当前研究提供结果证据，编辑验收也不自动提升物理验证状态。
