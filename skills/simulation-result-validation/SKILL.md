# 仿真结果验证

把已请求工况的仿真结果变成可审查的比较结论，回答“这些结果在什么条件下足以支持指定用途”。脚本成功只说明动作完成。允许报告已请求工况的观察趋势；因果机制、新论文路线或额外参数探索由上游决定。

## 接收与资料接口

读取 `simulation-task.md` 中的目标用途、工况、输出观测量与验收依据，`evidence/model-plan.md` 中的模型假设、参数、参考数据和来源，以及 `runs/` 中的原始结果、运行索引和数值状态。可以接收等价现有文件，按路径引用，不强迫重复建档。参数和数据应能辨认单位、观测定义、来源及角色（校准、验证或理论核验）。

先用现有材料完成可做的核验。缺少可对照数据或原件时，向请求者提出具名资源需求：哪个工况、观测量、原文/数据及缺失字段、为何影响哪个判断。由上游提供文献资源，仿真证据侧补提参数与参考数据；不要重新开展研究方向调研。只阻断依赖缺件的结论。

## 执行与返回

1. 确认比较双方的工况、单位、坐标、时间、采样区域、统计量及数据角色。构建必要的测量映射，把原始场量变成与实验或理论相同的观测量。涉及区域平均、仪器响应、插值、归一化或数据加工时读取 [比较与诊断](references/comparison-and-diagnosis.md)。保留原始值、映射方法及来源对应。
2. 核验会影响目标结果的数值质量：求解状态、相关守恒/平衡与边界条件，并根据已有证据和用途补充针对性的网格、时间步或误差检查。稳态无需强加时间步试验，确定性问题无需随机重复；随机总体预测按资料保留重复实现或估计依据。可请求 runner 补跑必要工况，不要求每工况三套网格、重新推导模型或执行固定门槛全集。
3. 按工况计算映射后结果与参考值的残差、适用误差指标及已知不确定度。真实世界用途优先比较实验数据；只有理论 benchmark 时说明它核验了什么，不能据此宣称实验有效。校准数据的拟合不能充当独立验证；未知不确定度明确记为未知。
4. 依据用途和事先明确的接受标准判断有效范围。没有标准时可提出与用途相称的判据供请求者解释，未获依据前返回条件性结论；不得看到偏差后拟合阈值。出现偏差时先排查本职测量映射和数据加工，再核对原数值状态；向 runner 或证据负责人请求具体修复/条件说明，并用同一症状重新比较。仍不能消除的偏差如实返回，不无限审查或自行启动机制研究。

## 状态含义

按工况及用途分别记录证据状态和判断状态，允许并存，不能合成单线升级阶梯：

| 状态 | 可以声明的含义 |
|---|---|
| `EXECUTED` | 求解执行完成，输出可定位；尚不代表数值或现实正确 |
| `NUMERICALLY_CHECKED` | 与目标相关的数值检查有证据，注明覆盖及误差限制 |
| `EXPERIMENT_COMPARED` | 已按同一观测定义与实验比较，可能一致也可能偏离 |
| `VALIDATED_FOR_USE` | 数值可靠性及独立参照支持明确工况/用途范围，同时注明 experimental 或 theoretical；理论用途成立不能称真实系统或实验已验证 |
| `INCONCLUSIVE` | 证据不足或可比性未解决，尚不能接受或拒绝该用途 |
| `FAILED` | 执行/数值检查失败，或依据既定标准该工况不支持指定用途；写明失败对象 |

## 完成条件

交付 `validation/report.md` 与 `validation/comparison.csv`，小任务可合为一个可读文件。包括可对照参考数据及来源、测量映射后的结果、各工况比较/残差/不确定度、状态及用途有效范围、未覆盖条件。理论核验、校准拟合和独立实验验证要能区分。报告关联 `runs/` 原始结果和加工产物，CSV 保留足以复核比较的字段。

返回请求者：已回答的问题、影响具体结论的缺件/偏差、具名待办及需要谁解释或验收。完成是已请求工况的比较得到有证据的结论或明确不可判定原因，不以文件存在、脚本成功或每项打勾代替。若请求者仅要局部验证，返回该部分及范围即可。
