# Research decisions, delegation and return

The coordinator keeps the current question, contribution, resource choices and argument. This does not authorize it to rewrite scientific facts. Specialist responsibilities remain separate even when one person or agent performs multiple roles.

| Responsibility | Owns | Returns | Cannot decide alone |
| --- | --- | --- | --- |
| Literature curator | Verified sources, historical line, methods and condition extraction | Located facts, disagreements, feasible comparisons, coverage limit | Novelty from search snippets; experiment truth |
| PaperSpine writer/planner | Reader model, journal fit, provisional contribution, argument and manuscript | Claim-to-section/figure plan, evidence gaps, draft, targeted revision questions | Invented results; unsupported validation |
| Simulation/experiment executor | Tool feasibility, faithful implementation, run/data provenance, necessary verification | Actual outputs, numerical/data adequacy, negative findings, options | Journal acceptance; changing raw data to fit |
| Mechanism analyst | Competing explanations, diagnostic quantities, uncertainty and interpretation | Evidence-bound interpretation and cheapest discriminating follow-up | Causality from a plot; universalization |
| Independent reviewer | Claim-specific challenges, source/figure consistency, reader objections | Severity, affected claims, evidence and feasible repair | Unlimited veto; majority vote as evidence |

Activate a role when its output can change a decision. A writer can ask the executor for a missing discriminating result; the executor can ask the curator about measurement conditions. Route direct question/answer artifacts through the coordinator and close them with requester interpretation. In Codex, collaboration tools can exchange messages among subagents; separate user-owned chats require their own authorization. Do not make extra chats merely to simulate roles.

## Task contract

Make the question narrow enough to have a useful return. For example, “Determine whether the ranking of two transport scenarios survives the estimated discretization error” is executable. “Make the model excellent” has no bounded answer.

Contract acceptance includes a scientific rationale: which QoI, which alternatives, what would falsify the proposed explanation, and how error/uncertainty affects the decision. Budget describes a default return point, not proof of adequacy. For an ordinary diagnostic use two meaningful attempts before reassessment; adjust for task cost and stage. All output paths belong to a named worker; workers do not edit the shared state.

Requester disposition answers: What is known now? Did this result change the paper argument? What stays uncertain? Is another run more informative than writing, literature extraction or a simpler control? Accepting a result file does not accept the hypothesis. Follow-up must identify new information or a different test rather than repeat an unchanged command.

## When rigor becomes local optimization

Before interrupting a worker for a delayed return, send a progress inquiry: why no return, current activity, existing candidate, remaining evidence question and the concrete value of further work. Ask for concise task status rather than private reasoning. Slow reasoning and consequential source checks justify continuation. Elapsed time cannot identify a revision loop. When the response or observable work establishes repeated revision without changed understanding, request the best current candidate with remaining limitations; send it to another agent for focused feedback before further revision. An unknown status calls for investigation and visible reassessment. Preserve explicit user cancellation and genuine transport failure as separate operational cases.

Symptoms are repeating the same refinement after the decision is stable, tightening tolerances without a claim-dependent reason, reading another near-identical source without changing coverage, or rebuilding an already usable figure while key evidence is absent. Ask for an incremental-value explanation. Stop optional work if there is none. Preserve the current limitation; do not claim higher adequacy than shown.

Counterexamples to premature stopping also matter: an effect smaller than numerical uncertainty, a ranking that reverses on refinement, wrong units, a nonconservative coupling, wrong experimental conditions, or a failed independent reference. These require correction or scope change. “We need a complete paper” never repairs them.

## Disagreement

Record the disputed claim, actual evidence, scope, alternative and smallest distinguishing test. Severity is attached to consequences for claims, not a reviewer's tone. A scientific stop-line pauses its dependent claim promotion and expensive downstream tasks; unaffected tasks can continue. A correction creates a new run/revision and invalidates dependent prior evidence. Scope reduction retires the original stronger claim; it does not relabel its failed evidence. Record remaining disagreement even after choosing a route.

## Context recovery

Task packets contain project purpose, current question/stage, relevant claims, facts/hypotheses, constraints, exact inputs, required output and budget. Read original passages for claims at issue. The coordinator carries a compact synthesis; raw solver logs and all literature extracts remain in artifacts. On resume inspect pending handoffs and invalidated claims first. Do not redo unchanged completed work.
