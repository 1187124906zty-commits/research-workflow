# 执行故障恢复

**何时读取：** handler 拒绝、运行时/路径/依赖错误、solver 非零退出、输出缺失或损坏、后处理失败、批量工况部分完成时。

## 先保全再修复

立即保存原请求/命令、输入修订、stdout/stderr、原生 receipt、job 目录和已有 raw/checkpoint。后处理、转换或清理不得覆盖原始证据。为每次尝试分配新 run-id，并记录父子关系与唯一变化；普通文本不做重复 hash，只有二进制来源、并发编辑保护或缓存绑定确有需要时才使用摘要。

## 按症状定位

- **工具/协议：** 核对实际 handler 名、参数 schema、会话要求、超时和原始拒绝；不把 `is_error`、畸形 payload 或未调用写成成功。
- **runtime：** 核对真实 executable/interpreter、版本、工作目录、路径映射、依赖、许可证、设备和权限。Windows/WSL/容器路径需在实际一侧验证。
- **输入映射：** 核对单位、参数类型、材料/区域编号、IC/BC/接口选择、符号/坐标、工况展开和固定环境。只修执行映射；物理值未知或改变方程时请求 `evidence/model-plan.md` 负责人。
- **solver：** 读取原生 traceback/log，区分解析、网格、线性/非线性、资源耗尽和数值异常。可以调整已授权的运行参数；不得偷偷改材料、边界、数据角色或用拟合使结果吻合。
- **输出：** 先查 raw 是否已有目标字段；有则重建索引或重新后处理。只有字段未导出、采样/association/时间覆盖错误且合同要求时才重跑。CSV 不替代必须保留的全场原生结果。

## 有界恢复

每轮只改变能检验根因的最小因素，并实际重跑相关探针或受影响工况。预算耗尽前优先保住已完成工况和关键 raw，不用缩小模型冒充正式目标。数值细化仅为指定 QoI/物理可信度服务，并记录理由与结论边界。

若连续两轮后症状和研究判断都未变化，停止同类重试，返回 router：当前状态、两轮变更与证据、最可能层级、已排除原因、可解除阻塞的具体信息/能力。需要新方程推导、新算法、重新选物理或改变验证观测时，具名请求相应 evidence/upstream 责任方。

批量运行中部分失败时不要抹去成功工况：逐工况列出状态、原始路径和可比性，整体返回 `PARTIAL`。后处理失败但 raw 完整时同样保留执行事实，先尝试从 raw 恢复；不得因图没生成而重跑昂贵求解。
