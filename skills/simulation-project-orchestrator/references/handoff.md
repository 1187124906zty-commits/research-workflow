# 上游与各阶段的交接

只在派发、缺件或恢复时读取。`simulation-task.md` 是当前任务入口，阶段文件是交付物，不是要求每个角色读全项目。

## 一个任务包

记录已有目标/命令原意、工况 ID 与待改变因素、固定物理条件、QoI 的定义/单位/位置/时间、原件位置、软件要求、输出和预算。上游已指定则引用，不重复填写。源文件和参数表保留原文定位和事实/假设状态。数值网格、时间步和求解器可按成熟方法选择，不要求与论文相同。

派发时加上该角色的问题、仅相关输入、独占输出路径、完成/返回条件。默认产物可为：

- 准备：`evidence/model-plan.md`、有需要时的参数/参考数据表；
- 执行：`runs/<case-or-run-id>/` 的原始结果/回执，`results-index.md`；
- 验证：`validation/report.md` 与比较表。

小任务可合并文件；适配器要求 JSON 才使用其格式。主代理更新当前入口，子代理写自己的产物，不覆盖别人的输出。

## 向上游请求资源

请求写在现有任务或 `missing-resources.md`：缺什么参数、数据或模型依据；目标物理系统与工况；可接受资料形式/观测范围；为什么影响哪个计算/验证；目标交付目录及返回位置；哪些工作可继续。已知标题/DOI则提供，未知时给工况和所需证据，不在仿真侧开启广泛检索。

上游选择自己的检索/下载 Skill。当前可用的 `sciencedirect-live-session-fetcher` 可接收标题/DOI、真实工作目录、文献目标目录和回传约定；本仿真 Skill 不代替其认证/下载流程，不向未经授权的外部聊天发送消息。文件到达后重新提取受影响项，保留已完成且无依赖变化的部分。

## 问题与恢复

反馈包括原异常定位、已完成本职检查、需要负责角色提供的答案/动作、影响的工况/结论、回复边界。回复给出证据、已回答/部分/未解决及变化；请求方记录采用理由、修复和原症状复测、剩余问题。接到文件不是接受结论。

复用项目的当前记录与版本。ResearchFlow 可用时主代理使用 `context PROJECT --task TASK_ID`、`record/decide` 保存尝试和处置；角色不需全读事件历史。其 API 以所选运行时的 `python -m researchflow --help` 及版本匹配文档为准；[维护仓库](https://github.com/1187124906zty-commits/research-workflow) 提供实现。没有运行时则在任务中保留等价的尝试/处置摘要。

恢复只带当前事实、未决项、已排除原因、有效/失效文件、成本及下一动作。修复经验有明确触发、原因、适用范围与有效证据后才推广；个案参数不进入通用 Skill。保留必要失败证据，日常草稿用版本控制，不不断复制报告。
